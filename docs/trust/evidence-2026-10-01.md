## Actual candidate inventory, not a clean bill of health

The scan found three candidates in required module `golang.org/x/crypto v0.55.0`:

| Advisory | Upstream package / assessment | KEV outcome in the supplied catalogue |
|---|---|---|
| CVE-2026-56855 / GO-2026-6355 | `ssh`, affected upstream versions before v0.56.0 | Not listed |
| CVE-2026-78662 / GO-2026-6354 | `ssh`, affected upstream versions before v0.56.0 | Not listed |
| GO-2026-5932 | Legacy `openpgp` packages; no fixed version reported | No CVE alias available for this correlation |

The [Go project](https://pkg.go.dev/vuln/GO-2026-6355) confirms the first SSH
advisory and [the second](https://pkg.go.dev/vuln/GO-2026-6354) confirms the other;
both fixes are in v0.56.0. The [OpenPGP advisory](https://pkg.go.dev/vuln/GO-2026-5932)
is package-specific and is not fixed merely by increasing the containing module's
version. These are public upstream advisories, not newly disclosed DNS Daddy exploits.

The existing [govulncheck job](https://github.com/jameshoulder/dnsdaddy/actions/runs/36842411953/job/110304378764)
ran `govulncheck ./...` with tool v1.8.0 and Go 1.27.1 on Linux amd64. It reported
zero affected imported packages and zero called-symbol vulnerabilities, while
noting three advisories in required modules whose affected code did not appear to
be called. This is useful scoped reachability evidence, not a blanket determination
for every build tag, platform, future code change or deployment.

The [public register](vulnerabilities.json) therefore retains all three as
`investigating`, with the automated evidence and upstream mitigation information.
No human applicability sign-off or dependency update is invented. Complete
supported-build review and any upgrade/retest decision remain maintainer tasks.
